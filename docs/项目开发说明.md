## 1. 项目概述

| 项 | 内容 |
|---|---|
| 项目名称 | LANPrint 局域网跨设备虚拟打印机 |
| 目标 | 局域网内把设备 A（服务端）的真实打印机共享给设备 B（客户端）。客户端安装后本地打印机列表出现虚拟打印机 `<服务端IP>_<共享名>`；用户向其打印时，内容被渲染为 PDF 并经 HTTP 传至服务端临时缓存，服务端调用本地真实打印机打印，完成后自动删除源文件，并向客户端回传“文件已接收”与“打印结果” |
| 运行系统 | Windows 10/11 x64（服务端与客户端） |
| 传输方式 | HTTP（局域网），完全开放（无令牌） |
| 交付物 | `lanprint_server_setup.exe`、`lanprint_client_setup.exe`（Inno Setup 安装包） |
| 当前版本 | 服务端 v1.0.0 / 客户端 v1.0.6 |
| 范围约定 | v1 每台服务端共享 1 台真实打印机（多台留待后续） |

## 2. 已确认的关键决策

| # | 决策项 | 结论 |
|---|---|---|
| 1 | Python 环境落实 | PyInstaller 内嵌运行时：exe 自带完整 Python，目标机免装、免检测 |
| 2 | 服务端打印引擎 | pypdfium2 逐页渲染 + Pillow DIB + win32print GDI 直写，任意打印机可用 |
| 3 | 客户端打印捕获 | **Windows 内置 Standard TCP/IP 端口监视器（tcpmon）本机回环端口 `LANPRINT`(127.0.0.1:9100) + agent 回环监听接收 PDF 流**（v1.0.3 起；无需任何第三方 DLL） |
| 4 | 客户端 PDF 生成 | 系统自带 `Microsoft Print To PDF`（v4 驱动）；打印内容统一渲染为标准 PDF 后经 HTTP 上传 |
| 5 | 传输架构 | HTTP 上传至服务端临时缓存目录 → 服务端队列化 → 调本地打印机打印（非数据流直写打印机） |
| 6 | 通信安全 | 完全开放，不做鉴权（局域网场景） |
| 7 | 结果通知 | Windows Toast 通知（不阻断操作）；上传后回 job_id，客户端轮询 `/job/{id}` 获取打印结果 |
| 8 | 权限模型 | 仅在安装/注册时要求管理员权限；日常运行（agent）无需授权 |

> **为什么最终采用“内置端口 + 回环 TCP”（重要演进记录）**
>
> 客户端需要在打印动作发生时拿到打印驱动输出（PDF）再上传，这一步依赖“端口监视器”。
> 经多版本实测（Windows 11 build 26200）：
> 1. **1.0.0**：Windows 自带 Virtual Port Monitor 的 Command 重定向端口在 26200 上已不可用（注册后 `EnumPorts` 整体报错）；
> 2. **1.0.1/1.0.2**：改用第三方 RedMon 重定向监视器，但系统事件 242 明确拒绝——`Microsoft Print To PDF` 属 **v4 驱动**，Windows 规定 v4 驱动只能绑定**内置**端口监视器，不能绑第三方监视器；而系统没有可再分发的 v3 PDF 驱动；
> 3. **1.0.3+**：唯一可行路径 = **内置监视器（tcpmon 的 Raw 协议）+ 本机回环 TCP 端口**：`Add-PrinterPort` 建 `127.0.0.1:9100`，v4 驱动天然兼容内置监视器；打印时 spooler 把 PDF 字节流经回环送到 9100，客户端 agent 监听该端口取走完整 PDF 上传。不依赖任何第三方 DLL，无权限残留（见 [功能模块说明.md](./功能模块说明.md)）。

## 3. 总体架构

```
【客户端设备】                                    【服务端设备】
 任意程序 → 打印 → 选择虚拟打印机
 "192.168.1.10_前台打印机"
   （MS Print to PDF 驱动渲染成标准 PDF）
        ↓ 内置 Standard TCP/IP 回环端口 LANPRINT(127.0.0.1:9100)
   agent 监听 127.0.0.1:9100 收到完整 PDF 流
   HTTP POST /print (multipart)  ──────────────→  HTTP 服务（默认端口 17878）
                                                    ↓ 文件落盘临时缓存 spool
                                                    ↓ 立即返回 job_id
                                                    ↓ 打印队列 Worker（FIFO）
                                                pypdfium2 渲染 PDF → GDI 写入
                                                    ↓
                                                真实打印机打印队列 → 出纸
                                                    ↓ 轮询 Windows 任务状态
                                                done → 删除临时源文件
                                                failed → 保留并记录原因
   GET /job/{id} 轮询打印结果  ←────────────────
        ↓
   Toast/弹窗通知：已接收 + 打印结果
   （服务端不可达：任务暂存 offline，agent 联网后自动重发）
```

## 4. 技术选型

| 组件 | 选型 | 用途 | 体积影响 |
|---|---|---|---|
| 语言 | Python 3.11+ | 稳定、PyInstaller 兼容 | 内嵌 ~10MB |
| HTTP 服务 | 标准库 `http.server`（ThreadingHTTPServer） | 零第三方依赖，多线程接收 | 0 |
| multipart 解析 | 自研流式解析（common/protocol.py） | 边收边落盘，大文件不占内存 | 0 |
| 打印 API | pywin32（win32print/win32api/win32gui） | 枚举打印机、GDI 写入、任务状态、托盘 | ~8MB |
| PDF 渲染 | pypdfium2 + Pillow | PDF→位图→DIB（仅服务端） | ~12MB |
| 端口监视器 | Windows 内置 tcpmon（Standard TCP/IP）回环端口 | 打印捕获到 PDF 流，兼容 v4 驱动 | 0 |
| 通知 | PowerShell WinRT Toast / ctypes MessageBox（兜底） | 结果弹框提示 | 0 |
| 托盘图标 | PIL 生成 ICO + user32 LoadImageW | 状态灯（在线/离线/暂存） | 0 |
| 打包 | PyInstaller（onefile + console） | 内嵌运行时 | — |
| 安装包 | Inno Setup 6 | 向导、提权、自启、防火墙、卸载 | — |

## 5. 通信协议 v1（HTTP，JSON）

### 5.1 API 一览

| 方法 | 路径 | 说明 | 成功返回 |
|---|---|---|---|
| GET | /ping | 连通性握手（安装校验、agent 状态灯） | `{ok, server, version, share_name, printer_online}` |
| GET | /status | 队列概况 | `{ok, waiting, printing, printer_online}` |
| POST | /print | multipart 上传打印文件（file、filename、copies） | `{ok, job_id, state}` |
| GET | /job/{id} | 查询任务结果 | `{ok, job_id, state, pages, error, created_at, finished_at}` |

### 5.2 请求/响应示例

```http
POST /print HTTP/1.1
Content-Type: multipart/form-data; boundary=----LANPrint

------LANPrint
Content-Disposition: form-data; name="filename"

报价单.pdf
------LANPrint
Content-Disposition: form-data; name="copies"

1
------LANPrint
Content-Disposition: form-data; name="file"; filename="报价单.pdf"
Content-Type: application/pdf

<二进制 PDF 数据>
------LANPrint--
```

```json
// POST /print 响应（文件接收情况）
{ "ok": true, "job_id": "a1b2c3d4", "state": "queued" }

// GET /job/a1b2c3d4 响应（打印结果）
{ "ok": true, "job_id": "a1b2c3d4", "state": "done", "pages": 3,
  "error": null, "created_at": 1790000000, "finished_at": 1790000031 }
```

### 5.3 任务状态机

```
queued（已接收待打印） → printing（打印中） → done（完成，删除源文件）
                                       └→ failed（失败，保留源文件 keep_failed_days 天，记录原因）
```

- 服务端重启后对遗留 queued/printing 且文件仍在的任务自动重新入队。
- 客户端轮询至终态弹出结果通知；超时（默认 10 分钟）按失败提示。

### 5.4 错误码

| HTTP 码 | 场景 |
|---|---|
| 400 | 参数缺失/文件字段缺失 |
| 404 | 未知路径或 job_id 不存在 |
| 413 | 文件超过大小上限（默认 200MB，可配置） |
| 500 | 服务端内部错误（如打印机不存在） |
| 503 | 打印机未就绪（脱机/错误状态） |

## 6. 服务端设计

### 6.1 安装流程（lanprint_server_setup.exe，管理员）

1. 选择安装目录，释放程序；
2. 安装完成自动运行配置向导 `configure`：选本机真实打印机 → 共享名（默认“我的打印机”）→ 端口（默认 17878）→ 上传上限；
3. 写防火墙入站规则（`netsh`，TCP 监听端口）；
4. 写 HKCU Run 自启（wscript 隐藏窗口），立即后台启动；
5. 生成 `%ProgramData%\LANPrint\config.json` 及各数据目录。

### 6.2 运行时行为

- 接收：ThreadingHTTPServer 并发接收，multipart 流式落盘，完整后登记任务并立即返回 job_id；
- 队列：单 Worker FIFO 串行（按接收时间排序）；
- 打印：pypdfium2 渲染 → DIB → GDI StartDoc/StartPage 写入共享打印机（适配纸张、横向页自动旋转）；
- 状态跟踪：队列快照差获取 Windows 作业 ID，EnumJobs 轮询至完成/错误/超时（默认 300s）；
- 清理：done 立即删除源文件；failed 保留 `keep_failed_days` 天后清理；
- 日志：`logs\server.log`（5MB×5 轮转）。

### 6.3 服务端配置（config.json）

```json
{
  "listen_host": "0.0.0.0",
  "listen_port": 17878,
  "printer_name": "HP LaserJet Pro MFP",
  "share_name": "前台打印机",
  "max_upload_mb": 200,
  "job_timeout_sec": 300,
  "keep_failed_days": 3,
  "spool_dir": "%ProgramData%\\LANPrint\\spool",
  "log_dir": "%ProgramData%\\LANPrint\\logs"
}
```

## 7. 客户端设计

### 7.1 安装流程（lanprint_client_setup.exe，管理员）

1. 向导页输入：服务端 IPv4 + 端口（默认 17878）+ 共享名；已注册过则从 client.json 自动预填；
2. **强制连通性校验**：`check-server --host <ip> --port <port>`（GET /ping）；不通 → 报错并中止安装；
3. `ssPostInstall` 阶段自动执行**完整注册** `register --server ... --port ... --share "..."`（无需手动命令行）：
   - 清理历史版本（Virtual Port Monitor / RedMon）残留；
   - 创建内置回环端口 `LANPRINT`(127.0.0.1:9100)（`Add-PrinterPort`，缺失才建）；
   - 创建/替换虚拟打印机：名称 `<IP>_<共享名>`，驱动 `Microsoft Print To PDF`，端口 `LANPRINT`（ctypes 直调 `AddPrinterW`）；
   - 保存 client.json（含 server_host/server_port/share_name/printer_display/local_tcp_port=9100）；
4. 写 HKCU Run 自启，`[Run]` 经 vbs 隐藏窗口启动 agent（托盘状态 + 回环接收）；
5. 注册失败会弹窗给出可复制的重试命令，用户以管理员身份重跑即可。

### 7.2 打印触发链路（用户视角）

1. 任意程序打印 → 选择 `<IP>_<共享名>`；
2. `Microsoft Print To PDF` 渲染为 PDF → spooler 经内置回环端口送到 `127.0.0.1:9100`；
3. agent 收到完整 PDF → POST /print → Toast“已发送到服务端，排队打印中”；
4. 轮询 /job/{id} → Toast“打印完成（共 N 页）”或“打印失败：原因”；
5. 服务端不可达 → Toast“无法连接，已暂存”，agent 联网后自动重发。

### 7.3 客户端配置（client.json）

```json
{
  "server_host": "192.168.1.10",
  "server_port": 17878,
  "share_name": "前台打印机",
  "printer_display": "192.168.1.10_前台打印机",
  "local_tcp_port": 9100,
  "poll_interval_sec": 3,
  "poll_timeout_sec": 600,
  "capture_dir": "%ProgramData%\\LANPrint\\capture",
  "offline_dir": "%ProgramData%\\LANPrint\\offline",
  "notify_dir": "%ProgramData%\\LANPrint\\notify",
  "log_dir": "%ProgramData%\\LANPrint\\logs"
}
```

## 10. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| v4 驱动只能绑内置端口监视器 | Microsoft Print To PDF 为 v4 驱动，系统事件 242 拒绝第三方监视器（RedMon 实测失败） | 已改内置 tcpmon 回环端口 + agent 接收（v1.0.3+），零第三方 DLL |
| Win11(26200) Virtual Port Monitor 失效 | 旧式 Command 重定向端口注册后 EnumPorts 报错 | 不再使用 Virtual Port Monitor；注册/卸载自动清理历史残留键 |
| pywin32 AddPrinter 结构限制 | PRINTER_INFO_2 dict 转换与 23 字段结构互斥，无法构造 | ctypes 定义 `PRINTER_INFO_2W` 直调 `winspool.drv!AddPrinterW` |
| 托盘图标 API 缺失 | 部分 pywin32 构建无 `win32gui.CreateIconFromResourceEx` | `_hicon_from_ico` 改用 user32 `LoadImageW`（临时 .ico） |
| 杀软对 PyInstaller exe 误报 | 常见现象 | 提供加白指引 |
| 打印/防火墙需管理员 | 系统限制 | 安装包提权；运行期 agent 无需授权 |
| 明文 HTTP | 局域网内可接受（已确认完全开放） | 后续版本可加令牌 |

## 11. 测试清单（对应验收）

- 阶段一（服务端）：上传→job_id→spool；FIFO 顺序；并发上传；>200MB 拒绝(413)；脱机/缺纸→failed 且保留源文件；done→删除源文件；重启→未完成自动重入队；自启/防火墙生效。
- 阶段二（端到端）：客户端离线时安装必须中止；Word/Excel/浏览器/图片打印→服务端出纸内容一致；多副本；横向页方向正确；“已接收/完成/失败”通知；服务端断网时打印→暂存→恢复后自动重发；双方重启自启正常；卸载后打印机/端口/自启项/防火墙/临时文件全部清理。

## 12. 卸载与清理

- 服务端卸载：停止进程 → 删防火墙规则 → 删自启 → 删程序文件（ProgramData 数据询问是否保留）。
- 客户端卸载：删虚拟打印机与回环端口 `LANPRINT` → 清理历史残留 → 删自启 → 删程序文件（数据目录询问是否保留）。
